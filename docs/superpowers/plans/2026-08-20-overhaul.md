# st-certify Overhaul Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Execution model for this plan:** five gated waves; inside a wave, lanes run as parallel agents in git worktrees coordinated from the lead session. Wave 1 is fully decomposed below. Waves 2–5 are structured work orders whose lane briefs the coordinator finalizes against the then-current tree at dispatch time (file:line references written earlier would be stale by then); their Files/Interfaces/Acceptance blocks here are binding.

**Goal:** Ship the approved overhaul — two-front-door IA, DocuSign-grade certificate flows with invites + notifications, sealed PDF export, verification ritual, touch-first designer, PWA/mobile, CI — per the spec.

**Architecture:** All off-chain (zero program changes). New Supabase tables for drafts/invites/notifications behind service-role RLS; Resend email behind a degrade-gracefully wrapper; pdf-lib + @signpdf behind a pluggable signer; route renames via permanent redirects; designer rebuilt on the existing 0..1 layout model.

**Tech Stack:** Next 15 App Router, React 19, zod 4, Supabase, Resend, pdf-lib 1.17.1, @signpdf 3.3.0 + node-forge, qrcode (SVG mode), react-moveable + react-selecto + @scena/react-guides + @dnd-kit, vitest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-20-overhaul-design.md` — read it first; this plan argues from it.

- [ ] **Step 1: Write the migration** — exact content (house style header comment explaining re-runnability):

```sql
-- Overhaul foundations: edition drafts, signer invites, notification log,
-- certificate verify codes. Re-runnable; RLS service-role-only (zero anon
-- policies), same posture as 0002/0003.

create table if not exists edition_drafts (
  id uuid primary key default gen_random_uuid(),
  meta jsonb not null default '{}'::jsonb,
  layout jsonb,
  template_sha text,
  chain_address text unique,
  created_by text not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table if not exists signer_invites (
  id uuid primary key default gen_random_uuid(),
  draft_id uuid not null references edition_drafts (id) on delete cascade,
  name text not null,
  role text not null default '',
  email text not null,
  token text not null unique,
  status text not null default 'invited'
    check (status in ('invited', 'accepted', 'expired')),
  wallet text,
  invited_at timestamptz not null default now(),
  accepted_at timestamptz,
  reminded_at timestamptz
);
create index if not exists signer_invites_draft_idx
  on signer_invites (draft_id);

create table if not exists notification_log (
  id uuid primary key default gen_random_uuid(),
  type text not null,
  recipient text not null,
  ref_id text not null,
  sent_at timestamptz not null default now()
);
create index if not exists notification_log_lookup_idx
  on notification_log (type, recipient, ref_id, sent_at desc);

alter table edition_drafts enable row level security;
alter table signer_invites enable row level security;
alter table notification_log enable row level security;

alter table certificates add column if not exists verify_code text;
-- 0003 §1 replaced anon's blanket SELECT with a column allowlist; new columns
-- are NOT covered and a column grant also governs WHERE clauses — without
-- this grant every anon verify query fails once the app selects verify_code.
grant select (verify_code) on public.certificates to anon, authenticated;
do $$
begin
  if not exists (
    select 1 from pg_indexes
    where indexname = 'certificates_verify_code_uidx'
  ) then
    create unique index certificates_verify_code_uidx
      on public.certificates (verify_code) where verify_code is not null;
  end if;
end $$;
```
