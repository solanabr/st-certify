# Attendance NFTs — Improvement Plan (seed)

**Context.** "Attendance NFTs" is a feature inside st-certify (repo `/Users/azrael/Developer/GigaClaude/st-certify`, app `apps/web`, Next 15 App Router, live at superteam.digital on **devnet**; deploys are manual `vercel deploy --prod`). Whitelisted creator wallets manage events at `/events` (wallet-standard + SIWS, Privy email fallback); each event has a secret claim link `/attend/<token>`; the server mints Bubblegum v2 cNFTs to participants (operator pays ~95k lamports each) from **one shared Merkle tree (depth-14 = 16,384 leaves, un-resettable)**. Supabase tables `attendance_events` / `attendance_claims` / `attendance_nonces` are RLS **service-role-only (zero anon policies)**. Real usage: Superteam Brazil IRL events — participants are mostly phones scanning a QR into a wallet-less mobile browser. `HELIUS_API_KEY` exists locally but is **not** in Vercel. This doc is the adjudicated output of a 40-idea scouting pass reviewed by three adversarial judges; verdicts are final.

## Decisions (already adjudicated — do not relitigate)

- **D1 Share page shape:** Minimal SSR card at `/nft/[assetId]` + OG metadata (plain event-image OG in v1, custom `ImageResponse` card as fast-follow) — value is chat-app link previews and crawlers don't run JS; no client interactivity, no DAS, no loop-back CTA in v1 (one judge would keep the CTA; parked P2).
- **D2 DAS/Helius indexer:** Avoid entirely, even decoratively — server-custodial mints with no transfer flow mean DB and chain cannot drift; DB is sole source of truth. Revisit only on a shipped transfer flow or a reported drift case.
- **D3 Dashboard viz depth:** Counts + lists + threshold capacity meters (one shared Progress component) only; no charts, sparklines, or chart libraries (dissent: one judge would allow hand-rolled SVG sparklines).
- **D4 Gamification:** None, full stop — personal `/me` history is the social ceiling; leaderboards/streaks/collector profiles would be a new product decision, not a feature.
- **D5 Priority:** Today-readiness correctness/security fixes (double-mint, RPC, noindex, nonce) jump every queue; mainnet-specific work is checklist-only until a cutover date exists (dissent: one judge would extract the ComputeBudget code now).

## Standing constraints

- Import fences (ESLint-enforced): chain SDKs only under `lib/chain/**`; `@wallet-standard` only under `lib/wallet/**`; supabase only under `lib/db/**`.
- API: POST route handlers + AppError envelope only; zod schemas shared client/server; creator surfaces gate via `requireAttendanceCreator`, participant surfaces via `requireUser`/SIWS.
- `attendance_*` tables are RLS service-role-only — any public read is server-side with an explicit column allowlist; `claim_token` never leaves the server except on creator surfaces.
- i18n mandatory: every string through `t()`, typed dicts pt/en/es in `lib/i18n/dict/attendance.ts` — no hardcoded copy.
- Brand: cream `#f5e8ca` / emerald `#008b4c` / yellow `#ffd23f`; Archivo headings + Inter body; light **and** dark themes via theme tokens, no raw colors.
- Five states per surface (loading/error/empty/populated/pending); no new runtime deps without strong cause (no chart libs, no animation libs, no DAS SDK).
